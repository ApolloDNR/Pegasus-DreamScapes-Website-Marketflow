## Global Constraints

- “Preserve the three homepage doors; keep representation and capital conversations distinct.”
- “Original payloads and receipts remain unchanged.”
- “Promotion creates a War Room only when the existing qualification gates are met.”
- “Unknown never appears green.”
- “A changed contract, buyer capacity, financing plan or exit must reopen the relevant review.”
- “The human remains responsible for decisions and releases.”
- “Full departmental execution, public inventory, buyer accounts, automated marketing, payments and a broader matching engine remain later releases.”
- Preserve the current website design/customer doors and HQ Command/Plan/Money/Record context. No redesign, new public inventory, auto-deals, auto-representation, provider sends, contract execution, payments, live SQL, new credentials, merges or public activation.
- Repository doctrine: `hq.*` / `shared.*`; approved public views/RPCs; work in `public.tasks`; activity in `shared.activity_log` / `public.activity_feed`; stage movement through `public.move_deal_stage`. No legacy `deal_*` revival.
- Initial private inquiry/buyer access stays active owner/admin only. Actor identity comes from verified authentication, never submitted account IDs, display names, email strings or user-editable JWT metadata. All selected owners/links must be active and in the same organization.
- Apollo’s Pin is human-authored Snapshot content: one sentence, trimmed length 20–500 characters; reviewer note 50–2000. It is not a password. No credential system, AI-filled Pin, historical-release rewriting or public 48-hour/paid-product promises.

## Review Focus

1. A legacy buyer inquiry or a representation inquiry must not silently acquire a new intent, changed retry hash, buyer profile or property Seed: Tasks 1, 3 and 4.
2. An unanswered request, false/unknown consent, suspended owner or revoked role must remain visibly blocked without lost drafts or unauthorized reads/writes: Tasks 2–4 and 9.
3. Lost responses, double clicks, two reviewers and concurrent approvals must not create duplicates or approve stale evidence: Tasks 2–8.
4. Imported/legacy records with missing fields must stay readable and explicitly incomplete, never automatically “verified,” consented or ready: Tasks 3, 6–8.
5. Mobile/keyboard navigation, browser Back, expiry and long/Unicode input must preserve context and allow recovery without leaking drafts between users: Tasks 1–3 and 9.

## Shared contracts and implementation decisions

These decisions settle routine choices so execution need not ask the user to design schemas.

### Mutation and privacy contract

`MutationResult<T> = {ok:true; data:T} | {ok:false; code:'invalid'|'forbidden'|'not_found'|'stale'|'conflict'|'unavailable'; message:string}`. Define it in `H/src/lib/website-inquiries/workflow-types.ts`; reuse it across new workflow/profile actions. IDs are UUID strings, versions positive integers, due times offset-aware ISO strings persisted as `timestamptz`; display the operator’s IANA timezone and do not interpret a date-only string as midnight UTC.

New authenticated write RPCs revoke EXECUTE from `PUBLIC`, `anon` and `service_role`, grant only `authenticated`, and explicitly re-resolve `auth.uid()` to an active, nonsuspended/nondeleted account and active organization membership inside the transaction. SECURITY DEFINER is permitted for these narrow canonical mutations and authorized private read RPCs, with fixed `pg_catalog` search path and fully qualified tables. Read RPCs recheck auth.uid(), active nonsuspended/nondeleted account, active owner/admin membership and active nonarchived/nondeleted organization before reading any data or counts. Revoke read RPC EXECUTE from PUBLIC/anon/service_role and grant only authenticated; never loosen raw inquiry/table grants to make reads work. New private tables enable RLS and deny direct table writes to browser/service roles. Existing raw inquiry acceptance/list service-only boundaries remain unchanged.

New mutation idempotency uses the existing `shared.idempotency_keys` pattern: endpoint + organization + authenticated actor + canonical request hash, lock before mutation, replay identical response, reject changed-content reuse, and audit in the same transaction. Replay authorization is rechecked; valid same-key replay precedes optimistic-version rejection. A client creates one key per unchanged submission attempt, retains it for network retries, and replaces it only after success or an edited payload. Keys must not become public status tokens.

`hq.intake_review_events` is append-only: id, org_id, entity_type ('inquiry'|'buyer_profile'), entity_id, actor_account_id, before_version, after_version, before_state JSONB, after_state JSONB, reason, idempotency_key and created_at. Only the verified mutation functions insert; same owner/admin read boundary, no direct mutations. Audit only identifiers, transitions and version/field-change names in general activity. Store sensitive before/after working content in a private `hq.intake_review_events` table protected by the same owner/admin boundary. Never copy raw inquiry payloads, capacity notes or consent contents into a general feed. Errors use stable sanitized messages, not SQL detail strings.

### Inquiry working state

Add `hq.website_inquiry_work`: `inquiry_id` primary key/FK to existing inquiry; `org_id`; `version default 1`; `classification`; `status`; `owner_account_id`; `next_action`; `due_at`; `due_timezone`; `reason`; `duplicate_of_inquiry_id`; `seed_id`; `buyer_profile_id`; reviewer/created/updated actor+timestamps. All linked rows are same-org, enforced in the mutation RPC, including duplicate targets. Original `hq.website_inquiries.envelope`, hash, receipt and created_at are immutable and untouched.

`classification = unclassified|property_candidate|buyer_mandate|representation|vendor|capital|development_partner|other`; `status = new|in_review|waiting|resolved|archived|duplicate|handed_off`. `new` can be unassigned and is visibly an exception. `in_review`/`waiting` require owner, next action 5–500 chars, date and IANA timezone. Entering waiting and closing/duplicate/reopen require reason 5–2000; duplicate requires same-org non-self target. `handed_off` is set only by atomic profile/Seed conversion, not a general edit. After handoff the child is the action’s source of truth; ordinary inquiry action edits are blocked. Do not create work rows automatically for all historical inquiries: read missing state as `new`, materialize on first explicit action.

### Private buyer profile

Add `hq.buyer_profiles`: UUID id; org/contact ids; owner; `version`; reviewed criteria JSON with schema discriminator; `status=active|paused|archived`; next action/date/timezone and nullable next_action_completed_at; reviewed_by/at; last_confirmed_at; nullable review_due_at; contact-consent and alert-opt-in evidence snapshots keyed by source inquiry, submitted subject and exact contact endpoint; `capacity_status=self_reported|pending_review|evidence_reviewed|expired`; private evidence reference/reviewer/date/expiry fields; created/updated timestamps. One active profile per `(org_id,contact_id)`; a private link relation `hq.buyer_profile_inquiries(profile_id,inquiry_id,org_id)` preserves each source. No entry in listing-specific `marketflow.buyer_interest`.

The human chooses an existing same-org contact or explicitly creates one. Existing contact linking never overwrites the contact. Linking a contact does not grant that contact or its different email/phone the source submitter’s consent. Preserve false/unknown and conflicting evidence separately; show permission for the matching submitted endpoint only and mark any other endpoint Not established. Suppressed/inactive endpoints remain suppressed. No outreach engine is added. Do not call `upsert_contact` with a null contact ID for conversion: its current email-match behavior updates a contact silently. For new contacts use a narrow audited create path within the profile transaction, reject a preexisting normalized email with candidate IDs, and serialize new buyer-profile contact creation by org/email. Never auto-merge; an email-free contact remains explicitly reviewed. New shared-contact fields are minimized to reviewed name/email/phone/company; private criteria/evidence stay in H’s private profile tables.

Capacity starts `self_reported`. Marking `evidence_reviewed` requires a private evidence reference, named authenticated reviewer, review timestamp and expiry; expiry derives an expired display state. It means evidence was reviewed, not a guarantee or regulated financial approval. No new upload facility. Profile freshness is the actual last-confirmed date plus explicitly chosen review date, not an invented universal expiration promise.

### Property bridge

`ReviewedPropertyInput`: `propertyAddress` 6–240, `contactName` 2–160, optional phone≤40/email≤254 with at least one valid path, `outreachReason` 10–2000, optional notes≤2000, owner, nextAction 5–500, dueAt/dueTimezone. Copy source values into an editable review form; reject over-limit values with correction instructions, never silently truncate. Consent is not an input boolean: derive exact contact=true and privacyAcknowledged=true plus original capturedAt/copyVersion from the stored inquiry. Missing/false/unknown evidence blocks bridge creation. Consent belongs to the original submitted subject and endpoint: reviewed whitespace/case/phone-format normalization may preserve identity, but changing to a different person or email/phone cannot reuse the source consent. Such changes remain blocked until separately captured consent exists; new consent capture is outside this release. New consent collection and public Snapshot delivery remain separate, unimplemented flows.

Create canonical `hq.submissions`/`hq.seeds` transactionally with human-normalized facts, sourceChannel `website_inquiry`, original consent provenance in `consent_recorded_context`, original captured consent time, reviewing actor attribution, owner/action/date, and no triage decision. Do not use the public-intake function, which creates public status identity and stamps fresh consent. Do not issue a public token. Record existing canonical event shapes plus a private inquiry link; preserve raw original inquiry as the evidence source. For linking an existing Seed require explicit same-org choice and a reason; do not overwrite its facts, ownership or consent. Existing-Seed handoff requires a nonarchived active target, active same-org owner and an incomplete nonblank next action with due/date zone; otherwise return conflict without handing off or suppressing the inquiry. The human must update the child separately first. Multiple source inquiries may link to one explicitly chosen existing Seed; each inquiry links to at most one Seed.
